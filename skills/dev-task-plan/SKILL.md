# 拆解开发任务

一次为一个已确认的范围产出开发任务计划。开发任务是协调单位：一个负责人、一个可独立验收的交付结果，可能跨多个 PR、跨天；它不是编码操作。

## 工作流程

1. **分析交付。** 读 PRD 与技术方案，列交付物、模块 / 服务边界、外部依赖、团队技能与可用时间、硬约束。标出每个跨团队或跨仓库的交接点。
2. **定任务粒度。** 一个任务必须有一个负责人、一个可独立验收的结果、清晰边界。按交付物或工作流切，不按文件、不按技术分层切。一个任务包含多个不相关结果就拆；两个任务无法独立验收就合。
3. **设计依赖图。** 画 DAG，箭头从前置任务指向依赖任务；检查无环；标关键路径并留缓冲。并行任务不能写同一个文件，也不能争同一个接口的归属。
4. **派负责人与里程碑。** 按技能与可用时间匹配负责人；里程碑要有可检查的结果，不只是日期。每个任务写任务级验收，验收必须能在不看代码的情况下观察到。
5. **写计划。** 按 `assets/task-plan-template.md` 输出任务清单、负责人、依赖、里程碑、集成点、风险与明确不做的范围。编码操作细节不写进来，交给编码操作拆解。
6. **自检并交付。** 按 `references/checklists.md` 逐条验；不过就改计划再验。通过后交付到 `docs/plans/<主题>-tasks.md`，汇报路径与 commit，停。

## 规则

- 开发任务是协调单位，不是文件清单；用文件数、行数当拆解单位，会切出无法独立验收的碎片。
- 一个任务只能有一个负责人；共同负责人等于没人负责。
- 依赖必须写方向；只写「有依赖」无法排期。
- 任务级验收不写「功能正常」「测试通过」，要写可观察结果或命令。
- 不替 Developer 决定文件名、函数名、提交顺序。
