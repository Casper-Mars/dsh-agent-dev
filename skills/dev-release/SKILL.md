# 代码发布

发布是工程动作：可重复构建、可验证产物、可回滚。

## Iron Law

> 没有回滚步骤，不发版。

## 什么时候用 / 不用

- 用：版本发布、热修复、依赖安全补丁、构建产物交付。
- 不用：产品 release notes、市场公告、CI 平台搭建。

## 流程

1. **定版本**：语义化版本；破坏性变更升 major，新增升 minor，修复升 patch。
2. **冻结范围**：只含已验收变更；未验收不进版本。
3. **可重复构建**：干净环境、锁定依赖、记录 commit 与构建命令。
4. **验证产物**：校验和、启动冒烟、关键路径。
5. **写变更记录**：用户可读的 changelog，按类型分组。
6. **灰度与回滚**：比例、观察窗口、停止条件、回滚命令。
7. **发布后检查**：错误率、关键指标、日志异常。
8. **归档**：版本、commit、产物、回滚记录。

## 门禁

| # | 门禁 | 通过线 | 不过怎么办 |
|---|---|---|---|
| 1 | 范围冻结 | 只含已验收变更 | 移出 |
| 2 | 构建可重复 | 干净环境成功 | 修构建 |
| 3 | 产物可验证 | 校验和 + 冒烟 | 不发布 |
| 4 | changelog | 用户可读、分类 | 补 |
| 5 | 回滚 | 命令 + 数据兼容 | 不发布 |
| 6 | 观察 | 指标 + 窗口 + 值班 | 补 |

## 输出契约

```text
版本：<x.y.z>
范围：<commit 区间 / 变更列表>
构建：<命令 + 环境 + 产物校验和>
验证：<冒烟项 + 结果>
changelog：<链接>
灰度：<比例 / 观察窗口 / 停止条件>
回滚：<命令 + 数据兼容说明>
观察：<指标 + 值班人>
```

## 反合理化

| 借口 | 现实 |
|---|---|
| 小版本不用回滚 | 任何版本都可能失败 |
| 本地能跑 | 构建环境不同 |
| changelog 自动生成就行 | 自动生成的是 commit，不是用户语言 |
| 先全量再观察 | 全量不可逆 |
| 依赖补丁很小 | 小补丁也可能破坏兼容 |

## 红旗

- 版本号随手改。
- 构建依赖本地缓存。
- 产物没有校验和。
- 回滚只写「重新部署」。
- 发布后没人看指标。

## 交接

- 产品发布说明：PM。
- 发布审批：Leader / CTO。
- 故障处理：`dev-systematic-debugging` + CTO 复盘。
